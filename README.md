# RAG_База_знаний

RAG-система для поиска информации в загруженных документах.

## О проекте

Мини-сервис реализует подход Retrieval-Augmented Generation (RAG).

Пользователь загружает документ, после чего система извлекает из него текст, разбивает текст на фрагменты, создаёт embeddings и сохраняет их в векторном индексе FAISS.

При поступлении вопроса система выполняет поиск релевантных фрагментов документа и передаёт найденный контекст языковой модели GPT-4o Mini через ProxyAPI.

Главный принцип системы: модель должна отвечать только на основании загруженного документа и не должна придумывать отсутствующую информацию.

Алгоритм работы
Пользователь загружает документ.
Система проверяет формат и размер файла.
Из документа извлекается текст.
Текст разбивается на небольшие фрагменты.
Для каждого фрагмента создаётся embedding.
Embeddings сохраняются в индексе FAISS.
Пользователь задаёт вопрос.
Вопрос преобразуется в embedding.
FAISS находит наиболее релевантные фрагменты.
Найденные фрагменты передаются в LLM как контекст.
GPT-4o Mini формирует ответ.
API возвращает ответ и источники найденной информации.
Защита от галлюцинаций

Система использует отдельную системную инструкцию для LLM.

Модель должна:

отвечать только по предоставленному контексту;
не использовать собственные знания для дополнения ответа;
не придумывать отсутствующие факты;
не делать предположений;
сохранять смысл информации документа.

Если ответ отсутствует в найденном контексте, система должна вернуть:

Информация не найдена в загруженном документе.

Конфигурация

Для работы с ProxyAPI используется переменная окружения:

PROXY_API_KEY

Настоящий API-ключ не должен храниться в Git-репозитории.

Для локального запуска необходимо создать файл .env в корне проекта:

PROXY_API_KEY=your_proxyapi_key_here

Файл .env добавлен в .gitignore и не должен загружаться в GitHub.

Тестирование

В процессе разработки были выполнены следующие проверки:

1. Проверка запуска API

Endpoint:

GET /health

Получен корректный ответ:

{
  "status": "ok",
  "document_loaded": false,
  "document": null
}
2. Загрузка документа

Был загружен текстовый документ.

Система успешно:

приняла файл;
извлекла текст;
разбила его на фрагменты;
создала embeddings;
построила FAISS индекс.

Результат:

{
  "status": "success",
  "message": "Документ успешно обработан и проиндексирован.",
  "chunks": 11
}
3. Проверка поиска и генерации ответа

После загрузки документа был отправлен вопрос, ответ на который присутствовал в документе.

Система вернула:

ответ;
найденные источники;
номера страниц;
номера chunks;
similarity score.
4. Проверка защиты от галлюцинаций

Был отправлен вопрос, информация о котором отсутствовала в документе.

Система вернула:

Информация не найдена в загруженном документе.

Таким образом, модель не стала придумывать ответ на основании собственных знаний.

Принцип защиты от галлюцинаций

В системном prompt явно указано, что модель:

должна отвечать только на основании предоставленного контекста;
не должна использовать собственные знания;
не должна придумывать отсутствующие факты;
не должна делать предположения;
должна сохранять смысл исходного документа;
должна сообщать об отсутствии информации, если ответ не найден.
Ограничения текущей версии

Текущая версия является демонстрационным прототипом.

Ограничения:

максимальный размер файла — 1 МБ;
поддерживаются PDF, TXT и DOCX;
одновременно используется загруженный документ;
FAISS индекс хранится в памяти приложения;
после перезапуска backend индекс необходимо создать заново;
нет постоянного хранения индексов;
нет авторизации пользователей;
система не предназначена для production-нагрузки.
Особенности обработки PDF

Для извлечения текста из PDF используется PyMuPDF.

Система рассчитана прежде всего на PDF-файлы, содержащие текстовый слой.

PDF, состоящий только из сканированных изображений, без OCR, может не содержать доступного для извлечения текста.
